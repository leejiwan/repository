## 1. 제품 개요 (Product Overview)

### 1.1 배경 및 목적
- 현대 사용자는 매일 10~20개의 할 일을 신속하게 기록하고 완료 여부를 관리할 수 있는 심플한 도구를 필요로 함.
- 별도의 회원가입이나 복잡한 서버 인프라 없이, 브라우저 환경에서 즉시 실행되며 새로고침 후에도 기록이 보존되는 초경량 단일 페이지 웹 애플리케이션(SPA) 구축.

### 1.2 핵심 목표
1. **극도의 사용성 및 속도**: 순수 바닐라 자바스크립트 기반으로 외부 종속성 없이 빠른 로딩 속도 보장.
2. **신뢰할 수 있는 데이터 보존**: `localStorage`를 활용하여 새로고침 및 브라우저 재접속 시에도 데이터 완벽 유지.
3. **직관적인 성취감 제공**: 전체 진행률(Progress Bar)을 실시간으로 시각화하여 사용자의 업무 몰입도 증대.
4. **명확한 맥락 분리**: '개인'과 '업무' 2개 카테고리 분류로 일상의 작업 집중도 향상.

## 2. 기술 스택 및 환경 제약 (Tech Stack & Constraints)

- **언어 및 표준**: HTML5, CSS3, Modern Vanilla JavaScript (ES6+)
- **프레임워크/라이브러리**: **일체 미사용** (React, Vue, jQuery, Tailwind 등 사용 금지)
- **데이터 저장소**: 브라우저 Web Storage API (`localStorage`)
- **실행 환경**: 최신 모던 브라우저 (Chrome, Edge, Safari, Firefox 등)
- **인프라/백엔드**: 없음 (서버리스/클라이언트 사이드 전용)

## 3. 데이터 모델 설계 (Data Schema)

### 3.1 Todo 아이템 객체 구조
```javascript
{
  id: "string",          // 고유 식별자 (crypto.randomUUID() 또는 Date.now().toString())
  text: "string",        // 할 일 내용 (최대 100자, 공백 제거 필수)
  category: "string",    // "personal"(개인) | "work"(업무)
  completed: false,      // 완료 여부 (true | false)
  createdAt: 1773620000  // 생성 타임스탬프 (ms)
}
```

### 3.2 로컬 스토리지 키 관리
- **스토리지 키**: `TODO_APP_DATA_V1`
- **저장 포맷**: JSON 문자열 (`JSON.stringify(todos)`)
- **로드 예외 처리**: 파싱 실패나 손상된 데이터 유입 시 `try-catch`로 방어하고 빈 배열 `[]`로 안전 초기화.

## 4. 기능 요구사항 정의 (Functional Requirements)

### FR-1: 할 일 추가 (Create)
- **입력 요소**:
  - 카테고리 선택 셀렉트박스/라디오버튼 (옵션: `개인(기본값)`, `업무`)
  - 텍스트 입력창 (`input[type="text"]`, placeholder: "새로운 할 일을 입력하세요...")
  - '추가' 버튼 (`Enter` 키 입력 시에도 동일 동작)
- **비즈니스 로직**:
  - 텍스트 앞뒤 공백 제거(`trim()`).
  - 빈 문자열인 경우 경고 피드백 제공 및 생성 방지.
  - 최대 100자 제한.
  - 신규 아이템은 목록의 최상단(또는 최하단)에 추가되며 기본 `completed: false` 상태로 생성.
  - 등록 완료 시 입력창 초기화 및 포커스 유지.

### FR-2: 완료 상태 관리 (Status Update)
- **사용자 인터랙션**: 할 일 항목 좌측의 체크박스 클릭.
- **비즈니스 로직**:
  - 해당 항목의 `completed` 값을 `!completed`로 반전.
  - 완료 시 텍스트 취소선(strikethrough), 텍스트 색상 연하게 변경(투명도 처리).
  - 체크박스 활성화 상태 표시.
  - 전체 진행률 바 즉시 재계산 및 갱신.

### FR-3: 할 일 내용 수정 (Edit / Update)
- **사용자 인터랙션**:
  - 항목 더블 클릭 또는 '수정' 아이콘 버튼 클릭 시 인라인 편집 모드로 전환.
- **비즈니스 로직**:
  - 기존 텍스트가 입력된 `input`으로 전환.
  - `Enter` 키 입력 또는 포커스 아웃(`blur`) 시 저장.
  - `Escape(ESC)` 키 입력 시 변경 취소 및 기존 텍스트 유지.
  - 수정 시에도 빈 값 방지 검증 적용.

### FR-4: 할 일 삭제 (Delete)
- **사용자 인터랙션**: 각 할 일 항목 우측의 '삭제' 버튼(X 또는 휴지통 아이콘) 클릭.
- **비즈니스 로직**:
  - 목록에서 해당 `id`를 가진 객체 즉시 제거.
  - 삭제 후 `localStorage` 동기화 및 진행률 바 갱신.

### FR-5: 카테고리 분류 및 필터링 (Category & Filter)
- **카테고리 구분**:
  - `개인(Personal)`: 배지 컬러 (예: 파란색/초록색 계열)
  - `업무(Work)`: 배지 컬러 (예: 주황색/보라색 계열)
- **필터 탭 UI**:
  - `전체(All)` / `개인(Personal)` / `업무(Work)` 탭 제공.
  - 선택된 탭에 해당하는 항목만 렌더링.
  - 탭 전환 시에도 체크 상태, 수정, 삭제 기능 정상 동작.

### FR-6: 전체 진행률 표시 바 (Progress Bar)
- **위치**: 상단 헤더 영역에 고정 노출.
- **계산식**:
  $$\text{진행률(\%)} = \begin{cases} 0 & (\text{전체 할 일 수} = 0) \\ \left\lfloor \frac{\text{완료된 할 일 수}}{\text{전체 할 일 수}} \times 100 \right\rfloor & (\text{전체 할 일 수} > 0) \end{cases}$$
- **UI 표시 정보**:
  - 게이지 바 (CSS `width %` 및 `transition` 애니메이션)
  - 텍스트 정보 병기: `달성률 XX% (완료 N개 / 전체 M개)`
  - 100% 달성 시 축하 강조 스타일(색상 변화 등) 적용.

### FR-7: 데이터 영구 저장 (LocalStorage Sync)
- **동기화 시점**: Create, Update, Delete 등 상태 변경이 일어나는 모든 순간.
- **복원 시점**: 앱 최초 로딩(`DOMContentLoaded`) 시 단 1회 읽어와 메모리 상태 복구 및 화면 렌더링.

## 5. UI/UX 및 디자인 가이드라인

- **레이아웃**: 데스크톱과 모바일 모두 최적화된 중앙 카드형 단일 레이아웃 (최대 폭 `540px ~ 600px`).
- **가독성 및 타이포그래피**: 시스템 기본 폰트(Pretendard, Apple SD Gothic Neo, Noto Sans KR 등) 적용.
- **인터랙션**:
  - 버튼 호버/클릭 시 미세한 피드백.
  - 진행률 게이지 바 변경 시 `transition: width 0.3s ease-in-out` 적용.
  - 완료 체크 시 즉각적인 시각 피드백.
- **접근성(Accessibility)**:
  - 키보드 전용 사용자(Enter, Tab, Esc)를 위한 입력 및 포커스 흐름 보장.

## 6. 개발 단계별 구현 계획 (Implementation Roadmap)

1. **Step 1: 마크업 및 스타일링 (HTML/CSS)**
   - 시맨틱 HTML 구조 설계 (헤더, 진행률 바, 입력 폼, 필터 탭, 할 일 리스트)
   - 모던하고 깔끔한 모바일-친화형 반응형 CSS 스타일 작성
2. **Step 2: 상태 관리 및 스토리지 모듈 (Storage & State)**
   - Todo 상태 관리 모델(`state`) 및 `localStorage` CRUD 유틸리티 함수 구현
3. **Step 3: 핵심 비즈니스 로직 및 렌더링 (Core Logic)**
   - Todo 추가, 완료 토글, 삭제 기능 구현 및 리스트 동적 렌더링
4. **Step 4: 인라인 수정 & 카테고리 필터링 (Enhancements)**
   - 카테고리별 탭 필터링 로직 구현
   - 인라인 더블클릭/버튼 클릭 편집 기능 구현
5. **Step 5: 진행률 계산 및 UX 폴리싱 (Polish & QA)**
   - 진행률 실시간 계산 및 게이지 애니메이션
   - 데이터 무결성 검증, 키보드 인터랙션, 크로스 브라우징 테스트
